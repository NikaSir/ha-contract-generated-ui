# Home Assistant NikaS — единый стандарт интерфейса специализированных панелей интеграций

> **ИСТОРИЧЕСКИЙ ДОКУМЕНТ:** заменён `NIKAS_SPECIALIZED_PANEL_UI_STANDARD.md` v1.6. Правила Back, панорамирования при 100%, Header, Bottom Tab Bar и brand ниже ненормативны при расхождении с v1.6.

**UI Standard v1.2**  
**Статус:** обязательный  
**Основной target:** iPhone Pro Max, portrait  
**Редакция:** 22.08.2026

## 1. Назначение

Специализированные панели интеграций должны выглядеть и работать как мобильные приложения внутри Home Assistant, а не как набор отдельных Lovelace-карточек. Предметная логика каждой интеграции остаётся своей, но оболочка и навигационная модель должны быть единообразными.

Базовая модель приложения:

`Header → Device Selector (только для нескольких однотипных физических устройств) → Content выбранного устройства → Bottom Tab Bar`.

- Header Back — куда выйти из специализированного приложения.
- Device Selector — какое физическое устройство сейчас выбрано.
- Bottom Tab Bar — какой раздел/аспект выбранного устройства сейчас открыт.

Эти уровни навигации нельзя смешивать.

## 2. Верхний Header

На каждом основном экране специализированной панели должен присутствовать один и тот же компактный Header.

```text
[← Назад]        Название        [Refresh]
                  краткий subtitle
```

### 2.1. Кнопка «Назад»

- Располагается слева.
- Иконка: `mdi:arrow-left`.
- Touch-target — ориентировочно 44×44 pt или больше.
- Выполняет явный Home Assistant navigate.
- Не использует browser history как каноническую логику возврата.
- Long press и double tap не должны выполнять действия устройства.

### 2.2. Заголовок

- Название приложения геометрически центрируется относительно viewport, а не свободного пространства между кнопками.
- На основном iPhone viewport название должно помещаться в одну строку.
- Допускается короткий subtitle: модель, контекст, версия UI.
- Версия — вторичная информация и не должна конкурировать с названием.
- Не создавать второй крупный дублирующий заголовок сразу под Header.

### 2.3. Политика иконок

Декоративную иконку интеграции/устройства рядом с названием в Header не использовать.

Она смещает визуальный центр и конкурирует с Back. Иконка может использоваться в sidebar, launcher-карточках, status-картах и navigation metadata, но не как часть стандартного верхнего заголовка.

### 2.4. Правая зона Header

- Допускается одна основная глобальная кнопка — обычно Refresh.
- При реальной необходимости допускается overflow `⋮`.
- Левая и правая управляющие зоны желательно делать одинаковой геометрии для визуального баланса.

## 3. Канонические parent routes

Кнопка Back всегда выводит в объявленную родительскую панель, независимо от того, откуда приложение было открыто.

| Специализированная панель | Канонический parent route |
| --- | --- |
| HO-SC-8W / Полив | `/dashboard-actions` |
| S8 OMNI | `/dashboard-actions` |
| Keenetic Hero 4G+ | `/dashboard-infrastructure/overview` |
| Stark SolarPower / UPS | `/dashboard-infrastructure/overview` |

## 4. Bottom Tab Bar

Если в приложении 3–5 основных разделов, они должны переключаться через полноширинный фиксированный нижний Tab Bar.

- Закреплён у нижней границы viewport.
- Занимает всю полезную ширину мобильного экрана.
- Не имеет внешних боковых/нижних отступов, как floating/pill card.
- Остаётся доступным при вертикальной прокрутке.
- Учитывает iOS Safe Area.
- Активная вкладка выделяется внутри общей панели.
- Используются иконка + короткая подпись.
- Последний контент должен полностью прокручиваться выше панели.

Floating Tab Bar с видимыми внешними зазорами считается несоответствующим стандарту.

### 4.1. Наборы вкладок

| Приложение | Bottom Tab Bar |
| --- | --- |
| HO-SC-8W | Обзор · Зоны · Программы · Диагн. |
| S8 OMNI | Обзор · Уборка · Станция · Сервис · Диагн. |
| Stark SolarPower | Обзор · Диагностика · История |
| Keenetic Hero 4G+ | Обзор · WAN/LTE · Трафик · Диагн. |

Для Keenetic допустим пятый раздел Failover, если он становится самостоятельным workflow:

`Обзор · WAN/LTE · Failover · Трафик · Диагн.`

## 5. Multi-device context: Device Selector

Если одна integration-owned панель обслуживает несколько равноправных физических устройств одного типа, выбор устройства становится отдельным постоянным уровнем интерфейса.

```text
HEADER
↓
DEVICE SELECTOR
↓
CONTENT ВЫБРАННОГО УСТРОЙСТВА
↓
BOTTOM TAB BAR
```

### 5.1. Обязательные правила

- Device Selector находится непосредственно под Header на всех основных разделах.
- Порядок устройств фиксирован и не меняется при выборе.
- Выбранное устройство обозначается только active-state.
- Допускается компактный status-dot/badge остальных устройств.
- Выбор устройства сохраняется при переходах между вкладками Bottom Tab Bar.
- Selector не исчезает на одном разделе и не появляется на другом.
- Весь основной Content ниже относится только к выбранному устройству.
- Не выводить подряд полноценные карточки/истории каждого однотипного устройства.

### 5.2. Где Device Selector не нужен

- Зоны полива — это каналы одного контроллера, а не отдельные peer devices.
- Робот и станция S8 OMNI — части одной системы, а не два peer vacuum.
- Ethernet и LTE — каналы одного роутера, а не два peer router.
- Если физическое устройство одно — Device Selector не требуется.

## 6. Stark SolarPower — референс multi-device

Stark SolarPower является референсной реализацией device-context. Правильная информационная архитектура уже просматривается на странице «Диагностика» и должна быть распространена на «Обзор» и «История».

```text
[←] Stark SolarPower [Refresh]
     UPS · UI vX.X.X

[ UPS Интернет ] [ UPS Котёл ]
----------------------------------------
CONTENT ВЫБРАННОГО UPS
----------------------------------------
Обзор | Диагностика | История
```

- UPS Интернет / UPS Котёл всегда находятся в одном и том же порядке.
- Выбор UPS сохраняется при переходе Обзор ↔ Диагностика ↔ История.
- В Selector можно показывать состояние обоих UPS маленькой зелёной/жёлтой/красной точкой.
- Обзор показывает одну полноценную карточку выбранного UPS.
- Диагностика показывает данные выбранного UPS.
- История показывает графики и события выбранного UPS.
- Второй полноценный UPS-блок ниже не дублируется.

## 8. Mobile-first требования

Основной приёмочный viewport: iPhone Pro Max, portrait.

- Без горизонтального скролла.
- Без обрезанных основных подписей.
- Частые действия и навигация доступны одной рукой.
- Header остаётся компактным.
- Device Selector не должен необоснованно вытеснять главный статус за первый полезный экран.
- Bottom Tab Bar не перекрывает контент.
- Есть достаточный bottom clearance, чтобы последняя карточка прокручивалась выше Tab Bar.
- Учитываются iOS Safe Areas.
- Светлая и тёмная темы остаются читаемыми.
- iPad/desktop — адаптация принятой мобильной иерархии, а не исходный дизайн.

## 9. Поведение сущностей и безопасность

- Не использовать raw Tuya DP write из Lovelace.
- Не обходить публичный API интеграции прямыми RCI/SNMP write.
- Не создавать фиктивные `entity_id` и неподтверждённые команды.
- `unknown / unavailable` никогда не трактуются как нормальное состояние.
- Управление допускается только через стабильный публичный API владельца интеграции.
- Long press на фактических entity-backed элементах по возможности открывает штатный Home Assistant more-info.
- Header, Device Selector и Bottom Tab Bar не выполняют побочные domain-actions.

## 10. Концептуальные navigation metadata

```yaml
panel:
  id: irrigation
  title: Полив
  path: /dashboard-irrigation
  icon: mdi:sprinkler
  owner: ha-ho-sc-8w
  expose_in_generated_ui: true
  preferred_view: overview
  header:
    title_alignment: viewport_center
    show_brand_icon: false
    back:
      icon: mdi:arrow-left
      parent_path: /dashboard-actions
  navigation:
    primary: full_width_fixed_bottom_tab_bar
    floating: false
```

Для multi-device приложения добавляется:

```yaml
device_context:
  selector: persistent_below_header
  preserve_across_views: true
  reorder_selected: false
  content_scope: selected_device_only
```

## 11. Требования по конкретным панелям

### 11.1. Stark SolarPower / UPS

- Убрать батарейную/brand-иконку из Header.
- `Stark SolarPower` геометрически центрировать.
- `UPS · UI v…` оставить вторичной центрированной строкой.
- Back слева, Refresh справа.
- UPS Интернет / UPS Котёл — постоянный Device Selector под Header на всех трёх разделах.
- Selection сохраняется при переключении нижних вкладок.
- Обзор, Диагностика и История показывают только выбранный UPS.
- Не дублировать второй полный UPS-блок ниже.
- Bottom Tab Bar: Обзор · Диагностика · История.

### 11.2. S8 OMNI

- Основной выход — Back, а не hamburger/Menu.
- `S8 OMNI` геометрически центрировать.
- Не размещать декоративную robot/integration icon возле Header title.
- Сохранить full-width bottom navigation: Обзор · Уборка · Станция · Сервис · Диагн.
- Composite robot + station state остаётся hero-информацией.
- Device Selector не требуется, пока панель обслуживает одну систему S8 OMNI.

### 11.3. HO-SC-8W / Полив

- Добавить явный Back.
- `Полив` геометрически центрировать.
- Модель/версию вынести во вторичную строку.
- Убрать декоративную каплю из самого Header.
- Каплю/спринклер использовать внутри status/navigation content, если полезно.
- Bottom Tab Bar: Обзор · Зоны · Программы · Диагн.
- Зоны не считать отдельными peer devices.

### 11.4. Keenetic Hero 4G+

- Сразу строить по этому стандарту.
- Back слева, центрированный title, Refresh/overflow справа при необходимости.
- Не размещать router icon рядом с Header title.
- Bottom navigation — полноширинная и фиксированная.
- Первый экран: Internet / active WAN / Ethernet / LTE / recent failover, а не системная диагностика.
- Ethernet/LTE — каналы одного роутера, Device Selector не требуется.

## 12. Критерии приёмки

- Header присутствует на каждом основном экране.
- Back явный и ведёт на объявленный parent route.
- Title геометрически центрирован на iPhone Pro Max portrait.
- В Header нет декоративной brand/device icon, смещающей title.
- Правая глобальная кнопка не нарушает центровку.
- Крупный title не дублируется ниже Header.
- При 3–5 основных разделах используется full-width fixed Bottom Tab Bar.
- Bottom Tab Bar прикреплён к нижнему краю и не является floating.
- Активная вкладка читается однозначно.
- Последний контент полностью прокручивается выше нижней панели.
- При нескольких peer devices Device Selector постоянен под Header на всех разделах.
- Выбранное устройство сохраняется между разделами.
- Порядок устройств не меняется из-за selection.
- Primary Content относится только к выбранному устройству.
- `unknown / unavailable` остаются явно ненадёжными состояниями.
- Навигационные элементы не могут случайно выполнить unrelated domain action.

## 13. Итоговое правило проекта

Integration-owned dashboards — это мобильные приложения внутри Home Assistant: явный Back сверху, геометрически центрированный title без декоративной Header-иконки, при необходимости постоянный Device Selector для peer physical devices, контент только выбранного устройства и полноширинный фиксированный Bottom Tab Bar для внутренней навигации.
