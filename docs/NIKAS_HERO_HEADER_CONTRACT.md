# NikaS Hero Header Contract v1.0

**Статус:** обязательное дополнение к NikaS UI Standard v2.2 для эксплуатационных карточек с верхней зоной состояния.
**Редакция:** 14.09.2026.
**Канонический источник:** `NikaSir/ha-contract-generated-ui`.

## 1. Назначение и приоритет документов

Контракт описывает верхнюю зону карточки: состояние устройства, пояснение,
запрошенную плашку связи, голубой декоративный элемент и изображение.
Она принадлежит рабочей области и прокручивается/масштабируется вместе с ней.
Это не фиксированный Header панели.

Единственный источник точных размеров плашки и декора —
[Connection Plaque and Blue Corner Contract v1.1](NIKAS_CONNECTION_DECORATION_CONTRACT.md).
Настоящий документ не вводит альтернативные отступы, шрифты или breakpoint.
Навигация заголовка панели определяется
[Navigation Contract v1.3](NIKAS_PANEL_NAVIGATION_CONTRACT.md),
а действие обновления — [Refresh Action Contract](NIKAS_REFRESH_ACTION_CONTRACT.md).

Плашка связи и декор добавляются только по продуктовому запросу.
Исключения «Дом сейчас» и StarLine сохраняются. Отсутствие плашки не требует
резервировать пустую колонку: состав карточки фиксируется в продуктовом контракте.
Изменение общей БЗ не является разрешением перестроить уже принятую панель.

## 2. Композиция и геометрия

При наличии плашки применяются все правила §§2–5 контракта v1.1:

| Элемент | Норма и владелец |
|---|---|
| Плашка | 168 × 58 CSS px; top/right 13 px от внутреннего края рамки |
| Внутренняя геометрия плашки | padding 11/12 px; лампа 10 px; зазор колонок 9 px; зазор строк 3 px |
| Текст плашки | 16/700 с line-height 17 px и 13/600 с line-height 14 px; общий font stack v1.1 |
| Узкая карточка | при внешней ширине менее 360 px заголовок переносится ниже; плашка остаётся справа сверху |
| Декор | круг 205 px; top −92/right −70 px; rgba(3,169,217,0.07) |
| Фото и форма карточки | пропорции, высота и внешний радиус принадлежат продуктовому контракту |

Вариант компоновки определяется немасштабированной шириной карточки.
Pinch не переключает breakpoint. Состояние и связь размещаются в отдельной
зарезервированной зоне, не поверх изображения устройства. От полной зоны
заголовка до отдельного изображения сохраняется зазор 12 px по v1.1.
Декор обрезается отдельным постоянным слоем; элементы управления и focus ring
не обрезаются вместе с ним.

Высота зоны состояния выбирается по полному словарю конкретной панели и
фиксируется для каждого утверждённого варианта ширины. При неизменной ширине
смена статуса, длины пояснения или загрузка фото не сдвигают начало изображения.
Универсальные координаты начала фото 124/194 px, breakpoint 400 px и обязательный
радиус 22 px из раннего черновика не принимаются: они конфликтовали с v1.1 и
продуктовой компоновкой. Размер изображения изменяется с сохранением пропорций.

## 3. Состояние, текст и оформление

Канал связи, актуальность данных и состояние устройства — независимые факты.
Их значения, словарь и цвета определяются UI Standard v2.2 §8 и продуктовой
моделью. Этот контракт не расширяет словарь плашки и не заменяет проверку
связи произвольным возрастом телеметрии. Выбранный режим не доказывает физическую
работу аппарата; последнее известное состояние не выдаётся за текущее.

Текст, предусмотренная продуктом иконка и семантический цвет строятся из одного
нормализованного состояния. При наличии иконки её слот постоянен; декоративная
иконка скрыта от assistive technology, полный текст статуса остаётся доступным.
Новые иконки и цветовые схемы не добавляются во все панели автоматически.

Полные краткие надписи проверяются при минимальной поддерживаемой ширине и с
fallback-шрифтом. Обрезка, троеточие и уменьшение обязательных шрифтов не служат
способом исправить компоновку. Пустое пояснение сохраняет предусмотренный слот.
Увеличение текста пользователем требует читаемого reflow и отдельной приёмки.
Декор не показывает состояние и не зависит от режима или цвета темы.

## 4. Обновление и проверка

Карточка, зона состояния, текстовые слоты, плашка, лампа, декор и контейнер
изображения сохраняют DOM-идентичность при телеметрии. Обновляются значения,
классы и доступное описание. Неизменившийся src повторно не записывается;
общий innerHTML, status-dependent key, анимация размеров и сброс масштаба
при обновлении не допускаются. CSS использует точные классы компонента.

Для production entrypoint фиксируются commit SHA, UI-версия, среда, размеры
host/карточки, масштаб и результаты:

1. Геометрия и шрифты плашки/декора проходят полную матрицу v1.1, включая
   внешнюю ширину карточки 359/360/361 px и светлую/тёмную темы.
2. Все поддерживаемые состояния, длинные надписи, потеря данных и восстановление
   сохраняют геометрию верхней зоны и начало фото при неизменной ширине.
3. Плашка и декор не смещаются при state-only обновлении: delta 0,
   допускается только численная погрешность измерения 0.1 CSS px по v1.1.
4. Проверены загрузка фото, повторное обновление, смена устройств и вкладок,
   прокрутка, pinch и сброс масштаба без пересоздания стабильных узлов.
5. Телефон, планшет и компьютер проверены по основной матрице UI Standard;
   приёмка в браузерной имитации отдельно от установленного HA/iPhone.

Проверка документа и его хэша подтверждает целостность нормы, а не приёмку
панелей. Внедрение выполняется отдельными PR; отсутствие измерений отмечается
GAP / not_verified. Keenetic, LIDER и Stark служат примерами согласованного
направления оформления, но не получают PASS только из-за публикации этой БЗ.
